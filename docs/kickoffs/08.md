This arrives in the same session as Kickoff 07. **Start it as soon as Kickoff 07's base is launched; don't wait for Kickoff 07 to finish.** Keep monitoring Kickoff 07: push its gate update and launch its arms on time, and come back to this between Kickoff 07 events. If the two ever compete for your attention, Kickoff 07 comes first.

**Unattended overnight.** The coordinator is asleep until about 08:00 IST. Anything genuinely open goes under "Decisions needed" in `docs/status_p23.md`. Launch every live run under `caffeinate -i`.

## Why

The study is now framed as a remedy test: when a colluding pricing agent is replaced, what carries the cartel across? P1 replaced the agent with the same model. The realistic remedy is switching to a different model, or a different vendor. P2 and P3 run P1's `history` and `full` arms with a smaller sibling and with another model family as the newcomer.

## Isolation (hard rules)

- All P2/P3 code goes in a **git worktree** at `../cartel-succession-p23`, on a new branch `exp/p23` off `origin/exp/p1`. Never edit files in the main checkout or switch its branch while Kickoff 07 is running, because Kickoff 07's arms launch from it.
- Status and log: **`docs/status_p23.md` and `docs/log_p23.md`** on `exp/p23`. Don't touch `docs/status.md`, `docs/log.md` or `docs/working_model.md`; the PI reconciles them later.

## 1. Models and checks (no GPU until the checks pass)

1. **P2 newcomer: Qwen3-8B.** Pin and log its Hugging Face revision. Same sampling as 14B with thinking on (0.6 / 0.95 / 20, max_tokens 8192).
2. **P3 newcomer: `openai/gpt-oss-20b`** (primary), with **`deepseek-ai/DeepSeek-R1-Distill-Llama-8B`** as the fallback.
   - Use each model's own recommended sampling settings, with reasoning on (for gpt-oss, reasoning effort "medium"). Record exactly what you used and why in the log.
   - **Switch rule:** if the primary's checks don't all pass within about 45 minutes of starting on it, switch to the fallback. If the fallback also fails, skip P3 and report. P2 carries on either way.
3. Make the app name, Volume and model selectable per app, keeping the 14B defaults. Fill each Volume with the existing CPU downloader pattern.
4. **Checks for each newcomer model:**
   - The locally rendered prompt matches the tokenizer's own chat template, byte for byte, with reasoning on. For gpt-oss, verify against its own chat template or format.
   - The price parser extracts the final price from the model's answer, not from its reasoning.
   - A `--dry-run` arm completes, and all tests pass.
5. Wire the arms `sib_history`, `sib_full`, `oth_history` and `oth_full`:
   - The newcomer in seat 1 is the new model, with no instruction.
   - Seat 0 stays the 14B instructed incumbent on `seat-swap-vllm`. You may call that app but don't manage it; a call that hits a cold start waits about 2–5 min, so allow for that in timeouts and retries.
   - Add a test that each seat goes to the right model and endpoint, and that the newcomer gets no instruction text.

If a check fails for P2, stop P2 and report. Don't work around a failed check.

## 2. Pre-register, then freeze (no GPU)

Add a "P2/P3" section to `docs/plan.md` on `exp/p23`:
- **Base:** none. Branch from P1's saved base snapshots at T = 150, seeds 200–214 (all passed P1's gate).
- **Arms:** `sib_history`, `sib_full` (P2) and `oth_history`, `oth_full` (P3). Each runs 60 rounds with the one-round shock at T+30, and uses P1's windows, thresholds and outcomes (`joins`, `enforces`, `overpriced`, `re_formed`). No probes.
- **Readings** (descriptive, against P1's `same_history` and `same_full` on the same seeds):
  - `*_history` `joins` high with `enforces` near 0 → the cartel price persists through a model switch; the data carries it.
  - `*_history` `joins` low → switching models breaks price persistence, which favors the replacement remedy.
  - `*_full` `re_formed` above `*_history` → memory carries enforcement across models.
- **Secondary:** a one-sided Fisher test of `*_full` vs `*_history` `re_formed`. It doesn't decide the headline.

Commit and tag `prereg-p23`. If P3 later switches to the fallback model, record that in the log; it's not a change to the plan.
